# 要求 — スリープ/復帰まわりで表示構成変更を叩き続けない

## 背景

クラムシェル運用の MacBook Pro で、復帰時に「黒画面 + マウスカーソルのみ」に
なりログイン画面が出ないことがある。watch.log には
`!! complete configuration failed: 3840x1620` が通算 30,469 件あり、
直近の 2026-11-12 は 15:18:30 から翌 00:58:19 まで 9.5 時間、10 秒間隔で
途切れずに続いていた。

## 調査で確定したこと (2026-11-16)

`pmset -g log` と watch.log を突き合わせた結果:

- **ディスプレイが消灯している間、復帰の適用は必ず失敗する。** 11/12 は
  15:17:42 に `Display is turned off`、15:18:30 に切断を検知して復帰を試み、
  以後ずっと失敗。同日 15:13:38 の失敗は 15:13:49 の `Display is turned on` と
  同じ秒に `-> HIGH (restored)` へ抜けている
- **システムはスリープしていなかった。** 9.5 時間のあいだ失敗ログに 60 秒超の
  空白が無く、pmset にも Sleep / Wake が無い。起きていたのはディスプレイ
  スリープだけ
- **嵐を止めたのは再起動。** 00:56 に SoftwareUpdate の自動再起動が走り
  01:04 に reboot。01:06:45 の `-> HIGH (restored)` は新プロセスの起動直後
  (`last == .unknown`) の無条件 restore で、蓋を開けた結果ではない
- **`CGCompleteDisplayConfiguration` は約 10 秒ブロックして失敗する。**
  失敗間隔は 3,478 回中 3,469 回がちょうど 10 秒。3 秒 tick はブロック中に
  溜まり、戻った瞬間に次が走るので、周期 = ブロック時間になる。メインスレッドは
  ほぼ 100% 塞がっていた (`update check` の行が毎回失敗行と同じ秒に出ている)
- **ターゲットの誤切り替えも実際に起きている。** `!! res_high mode not found:
  3840x1620` が 37 件。保存 UUID のディスプレイが一覧から消えた瞬間に別の
  ディスプレイへ切り替わり、UUID を上書きした痕跡

**確定していないこと**: 連打が黒画面の原因であること。連打は事実だが、
黒画面との因果は状況証拠しか無い。修正後に実機で確かめる。

## スコープ

1. スリープ中 (システム / ディスプレイ) は tick を止め、復帰後は猶予を置いて再開
2. 適用直前にディスプレイの状態を確認し、準備できていなければ CG を呼ばずに
   「保留」として返す。保留は失敗ではなく、前進もログ連打もしない
3. 本当に失敗したときは再試行を指数バックオフする (3s → 10s → 30s → 60s)。
   成功・接続状態の変化でリセット。同じ失敗ログは間引く
4. 保存済みターゲット UUID のディスプレイが不在のとき、別のディスプレイへ
   切り替えて UUID を上書きしない
5. メインスレッドのブロック回避 — **今回は見送り** (decisions.md 参照)

## 守ること

- ホーム学習の順序 (下げる直前の capture / ホーム状態での追従) と
  capture の active ガード
- 二段階 SETTLE、hooks は適用成功後のみ発火
- CShim には触らない
- watch.log は英語固定

## 受け入れ条件

- `make check` / `make test` が通る
- 保留中は前進せず hooks も発火しないこと、復帰後に ok が返れば HIGH へ
  遷移すること、連続失敗で呼び出しが抑制されること、接続状態の変化で
  バックオフがリセットされることがテストで示されている
- 保存 UUID が不在のとき UUID が書き換わらないことがテストで示されている
- 実機確認手順が提示されている
