# 決定事項

## 1. `String?` ではなく専用の enum にした

`remoteIP() -> String?` は「接続なし」と「判定不能」がどちらも nil に潰れる。
今回のバグはこの型の表現力不足そのものだったので、呼び出し側で気を付ける
のではなく型で分離した。`.unavailable` を追加すれば、以後どの分岐でも
コンパイラが取りこぼしを指摘してくれる。

## 2. `.unavailable` で `settling` をリセットしない

観測不能は切断の証拠ではない。リセットすると一過性の列挙失敗が SETTLE の
二段階確認を毎回巻き戻し、リモート接続中にいつまでも解像度が下がらなくなる。
`remote → unavailable → remote` は「連続 2 回の肯定的観測」として扱う
(テスト `testUnavailableProbeDoesNotResetSettling` が固定)。

## 3. `.unavailable` でも override / forceLow は従来どおり効かせる

手動フラグは接続状態に依存しない。早期 return を override / forceLow の
分岐より **後ろ** に置いたのはこのため。

## 4. CShim を触ることについて

CLAUDE.md は「CShim は触らない」としているが、その禁止の根拠は非公開 ABI の
構造体レイアウトとブロック歩行 (pack(4)・8 バイト境界) が静かに壊れること。
今回変更したのは sysctl 呼び出しのエラー処理のみで、構造体定義と歩行ループ
には一切手を入れていない。実カーネルでの非空列挙で歩行の健全性も確認済み。

## 5. `onProbeUnavailable` は tick ごとに発火させる

まとめずに毎回出すと以前と同じログ汚染になる懸念はあったが、
(a) C 側のリトライで一過性 ENOMEM はほぼ吸収されるため発火自体が稀になる、
(b) 恒常的に失敗しているなら毎 tick 出るほうが診断に有用、と判断した。
実運用でうるさければ throttle を入れる。
