# 要求 — 接続列挙の失敗を「接続なし」と区別する

## 背景

watch.log に `!! complete configuration failed` が通算 180 件。うち 174 件が
ホーム解像度 (3840x1620) で、壊れているのは *復帰* 方向。原因は
`.steering/20260725-public-app-phase2/blockers.md` に記録済み。

要約すると、sysctl の一過性失敗が「リモート接続なし」として観測され、
まだ画面共有が生きているのに復帰を試み、CG に拒否され、10 秒ごとに無音で
再試行し続ける。

## スコープ

1. **CShim**: `sysctlbyname` の 2 回目が ENOMEM で失敗したらバッファを広げて
   リトライする
2. **ConnectionMonitor**: 列挙エラーと「接続 0 件」を型で分離する
3. **StateMachine**: 観測が「不明」のとき前 tick の判定を維持する
   (= 不明を「接続なし」に倒さない)
4. 不明が続いたことを観測可能にする (無音で増幅させない)

## 非スコープ

- 復帰失敗そのものの backoff (別課題。本修正で発生頻度が下がるか様子見)
- CShim の構造体定義・ブロック歩行ロジック (CLAUDE.md の「触らない」対象。
  本修正が触るのは sysctl 呼び出しのエラー処理のみ)

## 受け入れ条件

- `make test` が全 pass
- 「不明」時に復帰も適用も試みないことがテストで示されている
- 「不明」が SETTLE の二段階確認を破壊しないことがテストで示されている
