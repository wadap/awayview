# decisions — SwiftBar プラグイン化

- **2026-07-20 メニューを 3 モード選択式に再構成 + 解像度ピッカー追加**
  - トグル 2 つ（固定/今すぐ低解像度）が分かりにくいというフィードバックを受け、
    「自動判定 / 高解像度（自宅） / 低解像度（外出）」のラジオ選択式へ
  - モードは既存フラグにそのまま対応（なし/override/force_low）。排他制御は
    プラグイン自身のサブコマンド呼び出し（bash="$0" param1=mode ...）に一元化
  - 解像度はサブメニューから選択し `$STATE_DIR/res_low` / `res_high`（WxH のみ）
    に保存。watcher の優先順位: res_low > config LOW_CMD、res_high > ホーム自動学習
    （res_high 未設定なら従来どおり自動学習 = 後方互換）
  - モード適用中の解像度変更は即再適用（watcher が適用済みコマンドを記憶して比較）
  - 解像度一覧は displayplacer list を 1 時間キャッシュ（毎 5 秒実行を回避）
  - メニュー選択時の displayplacer 引数は scaling:on 固定。細かく制御したい場合は
    選択を解除して config の LOW_CMD を使う

- **2026-07-19 案A（フラグファイル + 状態ファイル）を採用**
  - 対案B: launchctl bootout 方式（watcher 無改造）→ 復帰ロジックが UI 側に
    二重化し「固定中」と「異常停止」を区別できないため却下
  - 対案C: SIGUSR1 シグナル方式 → 結局状態ファイルが必要で複雑さに見合わず却下
  - 理由: 状態の真実を watcher に一元化し UI を薄く保つ。ファイル IF は
    ロードマップ②（Swift ネイティブ化）へそのまま引き継げる

- **2026-07-19 オーバーライドは「高解像度固定」のみ・手動解除まで有効**
  - 低解像度側の固定は作らない（YAGNI）
  - 時間失効はしない。📌 アイコンで固定中が常時見えるため解除忘れは視認で防ぐ

- **2026-07-19 プラグインは symlink 設置、watcher は従来どおり cp 設置**
  - プラグインは UI のみで開発中の反映速度を優先
  - watcher は launchd が参照する実行物なので設置物を固定する

- **2026-07-19 state ファイルは key=value（zsh source 可能）形式**
  - JSON 等は zsh からのパースが面倒。source 一発で読める形式を優先
  - 書き込みは tmp + mv でアトミック、変化時のみ

- **2026-07-19 実機確認を受けたスコープ変更: 手動の低解像度トグルを追加**
  - 実機で Tailscale 経由接続時に自動で下がらない事象が発生（原因調査と並行）
  - 検知に依存しない手動スイッチ `force_low` フラグを追加する
  - 優先順位: `override`(高固定) > `force_low`(低固定) > 自動判定。
    プラグイン UI 上は相互排他（片方を立てるともう片方を消す）

- **2026-07-20 接続検知を lsof から netstat へ変更（自動検知不能の根本原因）**
  - screensharingd は root 所有で、LaunchAgent(ユーザー権限)の lsof からは
    ソケットが一切見えない → 5900 への接続が原理的に検知できなかった
  - netstat -anv -p tcp は root 不要で全プロセスのソケットが見える
  - 実接続でのライブデバッグで特定（接続は従来どおり TCP 5900 / Tailscale IPv4 だった。
    前日疑った IPv6 は今回の直接原因ではないが対応は妥当なので残す）

- **2026-07-20 モード遷移フック on_low/on_high を汎用機構として追加**
  - 動機: モバイル利用時に Scroll Reverser(スクロール反転)を止めたい
  - 専用組み込みではなく config.zsh の関数定義（対案: SCROLL_REVERSER フラグ）。
    コアが特定アプリを知らず、今後の「モード連動」も config だけで拡張できる
  - 発火点は apply_low / restore_home の成功後のみ（復帰失敗時は発火しない）。
    フック失敗は log に記録するだけで watcher は止めない

- **2026-07-19 テスト容易性のため env 上書きを導入**
  - `SCREENSHARE_RES_STATE_DIR`（watcher/プラグイン共通）と
    `SCREENSHARE_RES_LAUNCHCTL`（プラグイン）を追加
  - lsof / displayplacer は既存の config 変数で差し替え可能なため、
    スタブによる自動テスト(`make test`)が SwiftBar・実接続なしで回せる
